# FSR Relative Level Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Report two FSR inputs as stable relative 0–100% levels using the approved measured endpoints.

**Architecture:** Keep the standalone FSR sketch. Sample/filter both raw ADC inputs, normalize separately, and print readable diagnostic output. No hardware upload.

**Tech Stack:** Arduino-ESP32 core 3.3.12, native analogRead/Serial, existing g++ host test tools.

**Spec:** docs/superpowers/specs/2026-10-26-fsr-level-design.md

## Global Constraints

GPIO34: 551 released, 135 pressed. GPIO35: 4095 released, 156.5 pressed. Relative percent only, no N. Do not modify HX711, Unity, MQTT or dependencies.

## Review Focus

- Pressed inputs decrease raw values, so percent must increase in the opposite direction.
- Unequal baselines must not couple the two channels.
- Beyond-endpoint raw readings must not exceed 0–100%.
- Filter startup must use actual readings, not produce a false press from zero initialization.
- Filtering must still respond to press/release, including millis rollover.
