# Unity Kitchen Catch playtest checklist

This checklist tracks actual Unity evidence separately from hands-on acceptance. Task 7 production kitchen, mascot, item, panel, rank, and ambient art is integrated. `LegacyRuntime.ttf` and silence remain temporary because the user-supplied licensed font and audio are not available.

## Verified in Unity automation

- [x] Boot routes to Main Menu; production UI creates and selects local profiles, preserves duplicate names by short player ID, selects Easy/Normal/Hard with a persistent selected tint after focus moves and after returning from Results, and rejects invalid Start configuration. PlayMode scene-flow and UI tests use an injected in-memory `ProfileStore`, so they do not write production `PlayerPrefs`.
- [x] Gameplay HUD reads score, three HP, remaining time, rank, difficulty, and 0–100% left/right simulated keyboard strength; it does not invent a force measurement. Pause selects RESUME for keyboard focus. Results selects RESTART and exposes MAIN MENU; Restart restores the bottom input HUD.
- [x] Results show end reason, profile, score, difficulty, played time, remaining HP, caught/missed/trash counts, max combo, highest rank, left/right strength mean/max and pressed duration, both-pressed time, balance or unavailable, and `— / Sensor not connected` for force. Focused PlayMode UI tests verify no valid input samples show unavailable strength mean/max, zero pressed/both time and unavailable balance/force; valid released keyboard samples show 0% strength rather than unavailable. They also verify literal Thai/markup text behavior. Actual Thai glyph shaping is pending the supplied font.
- [x] The authored camera and Canvas match at 1280×720, 1920×1080, 1024×768, 1080×1920, and a wide 2560×1080 target. Active UI rects remain within the 16:9 camera viewport; tall/wide render targets letterbox or pillarbox.
- [x] Actual Unity URP captures: [final menu](../verification/task6-captures-delivery/task6-menu-1920x1080.png), [gameplay 1280×720](../verification/task6-captures-delivery/task6-gameplay-1280x720.png), [gameplay 1920×1080](../verification/task6-captures-delivery/task6-gameplay-1920x1080.png), [gameplay 1024×768](../verification/task6-captures-delivery/task6-gameplay-1024x768.png), [gameplay 1080×1920](../verification/task6-captures-delivery/task6-gameplay-1080x1920.png), [pause](../verification/task6-captures-delivery/task6-paused-1920x1080.png), [results](../verification/task6-captures-delivery/task6-results-1920x1080.png). These are Unity test renders, not browser or manual-play screenshots. The 60-second Results screenshot is a scripted survival using real falling-object outcomes. Menu and gameplay text appear softer than pause/results text at the same 1920×1080 target; this remains for final visual QA with supplied font and production art.
