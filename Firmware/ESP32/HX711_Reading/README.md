# HX711 bench calibration

เปิด `HX711_Reading.ino` ด้วย Arduino IDE ใช้ไลบรารี **HX711 by Rob Tillaart 0.6.5** ที่ติดตั้งอยู่ โค้ดใช้ API `begin(data, clock, fastProcessor, doReset)` ของไลบรารีนี้ ไม่ใช่สเก็ตช์สำหรับ HX711 ทุกไลบรารี

| ช่อง | พิกัด Load Cell | DT | SCK | Counts/g |
|---|---|---|---|---|
| CH1 | 1 kg | 32 | 18 | -2449.84 |
| CH2 | 5 kg | 33 | 4 | -429.11 |

## วิธีลอง

1. เลือกบอร์ด ESP32 และพอร์ตให้ตรงกับอุปกรณ์จริง แล้ว Verify/Upload เอง ไม่มีการอัปโหลดจากการแก้ไฟล์ครั้งนี้
2. วางอุปกรณ์ในตำแหน่งใช้งานโดยไม่มีน้ำหนักหรือแรงมือกด คงที่ตลอดการ tare ทั้งสองช่อง
3. เปิด Serial Monitor ที่ **115200 baud**; startup จะ tare ทั้งสองช่อง ถ้าการเปิด Monitor ทำให้บอร์ด reset จะ tare อีกครั้ง
4. หากเริ่มต้นโดยมีของวางอยู่ ให้เอาออกแล้วส่ง **`t` หรือ `T`** เพื่อ tare **ทั้งสองช่อง**; ใช้ line ending แบบใดก็ได้ อย่า tare ขณะวางน้ำหนักหรือบีบ
5. รอ `CH1: tare OK.` และ `CH2: tare OK.` แล้ววางน้ำหนักอ้างอิงบนช่องที่ต้องการ โดยอีกช่องไม่รับน้ำหนัก

ตัวอย่างรูปแบบ (ไม่ใช่ผลจากบอร์ดจริง):

```text
CH1: 228.00 g | Estimated Force: 2.2359 N
CH2: 0.00 g | Estimated Force: 0.0000 N
```

`not ready` หมายถึงยังไม่มี sample พร้อมอ่าน; `not calibrated` หมายถึง tare ไม่สำเร็จ ต้องเอาน้ำหนักออกแล้วส่ง `t` ใหม่ ช่องที่พร้อมจะรายงานแยกกัน ไม่ใช้เงื่อนไขว่าทั้งสองต้องพร้อมในเวลาเดียวกัน ค่าเล็กน้อยติดลบคงไว้เพื่อดูศูนย์เลื่อน ไม่ใช้ abs และไม่บังคับให้เป็น 0

อ่านเฉลี่ย 3 samples ต่อช่องและ tare เฉลี่ย 5 samples ตรวจเวลารอก่อนแต่ละ sample (250 ms ตอนรายงาน / 1000 ms ตอน tare) ไม่เรียก begin/reset ที่อ่านแบบไม่จำกัดเวลาทันที ใช้ power cycle ของ HX711 เพื่อกลับสู่ channel A/gain 128 แทน คำสั่ง tare รอทีละช่อง ชุดนี้เป็น bench test ไม่ใช่ input loop สำหรับเกม 60 FPS

## ที่มาของค่าและข้อจำกัด

- ตัวคูณมาจากข้อมูล 525 g และจุดไม่มีน้ำหนักเดิม แล้วตรวจเทียบกับ iPhone ที่ผู้ใช้ระบุ 228 g ใน `C:\Users\Arc\Downloads\CPS_Calibrate\Final.txt` ไม่ได้นำช่วงก่อนวาง/กำลังวางมารวมเป็นช่วงนิ่ง
- ผลตรวจจากไฟล์ก่อนปัดตัวคูณ: CH1 ประมาณ 227.33 g (-0.29%), CH2 ประมาณ 227.56 g (-0.19%) ไม่ใช่การรับรองความแม่นยำหรือผลหลังอัปโหลดสเก็ตช์นี้
- จุด 83 g ยังไม่สอดคล้องกับจุดหนักกว่า จึงใช้ calibration นี้เป็น **ชั่วคราว**; ตรวจ 83/228/525 g และยกออกดูศูนย์ซ้ำ อย่าคาดหวังว่า 83 g ต้องตรงหลังเปลี่ยนตัวคูณนี้
- ต้องใช้การยึด จุดรับแรง และทิศทางแรงเดียวกับตอนสอบเทียบ หากเปลี่ยนกลไกต้องตรวจใหม่ ห้ามบีบจนเกินพิกัด โดยเฉพาะตัว 1 kg
- `Estimated Force (N) = grams × 0.00980665` เป็นแรงประมาณจากน้ำหนักเทียบเท่าบนเซนเซอร์ ไม่ใช่ความแรงบีบมือเชิงคลินิก
- ตัวคูณอยู่ช่วงต้นไฟล์ แก้แยกช่องได้; ศูนย์วัดใหม่ทุก startup/คำสั่ง tare ไม่บันทึกลง flash และไม่ใช้ offset เก่าจากไฟล์ log
- ไลบรารี `read()` ยังมี blocking wait ภายใน หากอุปกรณ์หลุดพอดีระหว่าง readiness check กับการ read ครั้งนั้น อาจค้างได้ แม้ป้องกันกรณีช่องไม่พร้อมก่อนอ่านและระหว่าง samples แล้ว

ไม่มีการแก้ FSR, Unity, MQTT หรือเกณฑ์แรง 0–100 ในงานนี้
