# FSR relative pressure level

เปิด `FSR_Reading.ino` แล้วเลือกบอร์ด/พอร์ต ESP32 ของคุณใน Arduino IDE และอัปโหลดเอง จากนั้นเปิด Serial Monitor ที่ **115200 baud** ไม่ต้อง tare สเก็ตช์นี้ใช้ช่วงที่ผู้ใช้วัดและยืนยันไว้แล้ว

| ข้าง | ADC pin | ปล่อย = 0% | บีบอ้างอิง = 100% |
|---|---|---|---|
| Left | GPIO34 | 551 | 135 |
| Right | GPIO35 | 4095 | 156.5 |

ที่มา: `C:\Users\Arc\Downloads\CPS_Calibrate\Yahoo.txt` ใช้ค่ามัธยฐานแยกแต่ละข้าง ผู้ใช้ยืนยันว่าซ้าย 551 คือปล่อยจริง ไม่บังคับให้สองข้างมีจุดปล่อยเท่ากัน ค่า 100% อ้างอิงชุดข้อมูลหัวข้อ “บีบสุด” ที่ผู้ใช้บันทึก ไม่ต้องบีบสุดใหม่เพื่อใช้งานทุกครั้ง

สูตร: `level = clamp((released - filteredRaw) / (released - pressed) * 100, 0, 100)` เป็น **ระดับการกดสัมพัทธ์ ไม่ใช่หน่วย N หรือเปอร์เซ็นต์แรงจริง** ไม่ได้ยืนยันว่ากดครึ่งแรงจริงจะเท่ากับ 50%

ตัวอย่างรูปแบบ:

```text
FSR Left: raw=343 filtered=343.0 level=50.0%
FSR Right: raw=4095 filtered=4095.0 level=0.0%
```

อ่าน ADC 12-bit ทุก 20 ms; กรองแบบ exponential ด้วย `FILTER_ALPHA = 0.2` และแสดงผลทุก 100 ms ค่าเริ่มต้นของตัวกรองใช้ค่าที่อ่านจริง เพื่อลดการกระโดดจากค่าเริ่มต้น 0 ระหว่างเปิดบอร์ด ค่ากรองจึงตามหลังค่าดิบเล็กน้อยหลังบีบ/ปล่อย การแสดงระดับ 0–100% จำกัดผลลัพธ์เท่านั้น ไม่ใช่การตัดค่าดิบออก

## ตรวจและปรับเอง

- ปล่อยมือทั้งสองข้าง: `level` ควรอยู่ใกล้ 0%; เล็กน้อยเหนือ 0% อาจเกิดจาก noise หรือจุดปล่อยเปลี่ยน ไม่มี dead zone หรือคำสั่งขยับตัวละครในสเก็ตช์นี้
- กดทีละข้าง: ระดับของข้างนั้นเพิ่มขึ้น และลดลงเมื่อปล่อย อีกข้างใช้ช่วงของตัวเอง
- กดแรงกว่า/เบากว่าจุดอ้างอิง: ระดับถูกจำกัดที่ 100%/0% แต่ยังเห็น raw และ filtered เพื่อวิเคราะห์
- ปรับ `LEFT_RELEASED`, `LEFT_PRESSED`, `RIGHT_RELEASED`, `RIGHT_PRESSED` ที่ต้นไฟล์ถ้าจุดอ้างอิงเปลี่ยน แต่สำหรับวงจรชุดนี้ค่า RELEASED ต้องมากกว่า PRESSED ห้ามตั้งเท่ากัน
- เปลี่ยน FILTER_ALPHA ให้น้อยลงเพื่อให้ค่านิ่งขึ้นแต่ตอบสนองช้าลง ใช้ค่ามากกว่า 0 และไม่เกิน 1
- ไม่เปลี่ยน attenuation ของ ADC จากค่าเริ่มต้นเดิม หากเปลี่ยนบอร์ด การต่อวงจร ตัวต้านทาน ไฟเลี้ยง หรือการตั้ง ADC ต้องเก็บจุดอ้างอิงใหม่

ขวาตอนปล่อยอยู่ที่เพดาน ADC 4095 จึงยังไม่ยืนยันความละเอียดช่วงกดเบา ค่าสูงสุดที่ค้างอาจไม่สามารถแยกกรณีปล่อยจริงออกจากปัญหาการต่อบางชนิดได้ ไม่ควรถือว่าสเก็ตช์นี้ตรวจพบเซนเซอร์หลุดแล้ว

การแก้ครั้งนี้ไม่มีการอัปโหลดบอร์ด ไม่เปลี่ยน HX711, Unity, MQTT หรือเพิ่มไลบรารี
